# Система учета реактивов и склада лаборатории (Lab 1)

Данный проект представляет собой консольное приложение (CLI) для управления лабораторными реактивами, партиями (бутылками) и движениями по складу (приход/расход).

Проект выполнен в рамках Лабораторной работы №1.
**Предметная область:** 2 (Реактивы и склад).
**Вариант хранения:** 3 (Хранение в памяти с использованием `LinkedHashMap` для сохранения порядка добавления).

## 🏗 Архитектура и принципы
Проект строго следует принципам **SOLID** и разделен на логические слои:
* `domain` — изолированные сущности (POJO) со строго `private` полями.
* `repository` — слой доступа к данным (имитация БД в памяти с автогенерацией ID).
* `validation` — отдельные классы валидаторов. Данные проверяются строго *до* сохранения.
* `service` — инкапсулированная бизнес-логика (связывание сущностей, пересчет остатков на складе при расходе).
* `cli` — пользовательский интерфейс. Вся обработка исключений (без вывода stacktrace) происходит здесь.

## 📋 Доступные команды CLI

Все команды обрабатывают ошибки ввода безопасно, выводя понятные сообщения без падения программы (без stacktrace).

### 🧪 Реактивы (Reagents)
* `reag_add` — интерактивное создание нового реактива (запрашивает название, формулу, CAS, класс опасности).
* `reag_list [--q TEXT]` — вывод списка всех реактивов. Опция `--q` позволяет искать по названию, формуле или CAS-номеру.

### 📦 Партии / Бутылки (Reagent Batches)
* `batch_add <reagent_id>` — интерактивное добавление новой партии/бутылки на склад.
* `batch_list <reagent_id> [--active]` — вывод списка всех бутылок для конкретного реактива. Опция `--active` скрывает архивные.
* `batch_show <batch_id>` — вывод подробной карточки бутылки с текущим остатком и локацией.
* `batch_update <batch_id> field=value` — обновление данных бутылки. Разрешенные поля: `location`, `label`, `expiresAt` (формат YYYY-MM-DD), `status` (ACTIVE/ARCHIVED).
* `batch_archive <batch_id>` — перевод бутылки в статус ARCHIVED (архивация/списание). После этого движения по ней запрещены.

### 🔄 Движения по складу (Stock Moves)
* `move_add <batch_id>` — интерактивное создание складского движения (`IN`, `OUT`, `DISCARD`).
  > **Важно:** При `OUT` или `DISCARD` программа проверяет остаток и не даст списать больше, чем есть в наличии. Остаток в бутылке пересчитывается автоматически.
* `move_list <batch_id> [--last N]` — вывод истории движений по конкретной бутылке (опционально только `N` последних записей).

### 📊 Отчеты (Reports)
* `stock_report [--expires-before YYYY-MM-DD]` — генерация простого отчета по складу. Опция позволяет вывести только те партии, у которых срок годности истекает до указанной даты.

### 🛠 Системные
* `help` — вывод списка всех доступных команд.
* `exit` — корректное завершение работы приложения.
